# Runtime Attribution

This section breaks down performance across layers and defines the
Phase D archive alert threshold policy used by operations.

## Layer Attribution

The attribution model partitions cost into:

- core engine (Rust)
- FFI boundary
- hosted runtime (dotnet / wasm)

### Key insight

Most cost is not in CRDT logic.

It is in:

- serialization
- boundary crossing
- signing
- transport

### Interpretation

- Rust core: nanoseconds to microseconds
- FFI: 2–10x overhead
- hosted runtime: 10–50x overhead depending on payload size

### Conclusion

The system is not compute-bound.

It is orchestration-bound.

## Archive Alert Threshold Policy (Phase D)

The alert policy below is the source-of-truth used by the operator runbook
and dashboard wiring.

Reference evidence:

1. Threshold artifact: `docs/acceptance/archive-phased-alert-thresholds-run01.json`

3. Runbook wiring: `docs/acceptance/archive-phased-operator-alert-runbook-run01.json`

### Cache miss ratio thresholds

Formula:

`miss_ratio = miss / (hit + miss)`

Required sample guards:

1. 15m windows require `hit + miss >= 200`
2. 5m fast-burn window requires `hit + miss >= 100`

Thresholds:

1. Warn: `miss_ratio > 0.10` over 15m
2. Critical: `miss_ratio > 0.25` over 15m
3. Critical fast-burn: `miss_ratio > 0.40` over 5m

### Object/file parity drift thresholds

Alert on absolute p95 delta between object and file lanes.

Warn thresholds (15m window):

1. export p95 delta > 1.0 ms
2. validate p95 delta > 1.0 ms
3. import p95 delta > 2.0 ms

Critical thresholds:

1. any operation p95 delta > 5.0 ms over 10m
2. import p95 delta > 3.0 ms over 10m

### Absolute latency safety rail thresholds

1. Warn: operation p95 > 50 ms over 15m
2. Critical: operation p95 > 100 ms over 10m

### Baseline anchor (run-04)

1. export p95 abs delta: 0.05 ms
2. validate p95 abs delta: 0.02 ms
3. import p95 abs delta: 0.26 ms
4. peak memory: 13.0 MB

### Operator action contract

1. L1 acknowledges within 10 minutes.
2. Warn route escalates to L2 when sustained for 15 minutes.
3. Critical route pages L3 and enters freeze workflow.
4. Recovery requires 30 consecutive minutes below warn thresholds.
