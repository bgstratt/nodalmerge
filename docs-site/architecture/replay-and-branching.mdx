# Replay and Branching

Every NodalMerge room is a deterministic event graph.

---

## Replay

A room can be reconstructed by replaying:

- transaction log
- policy timeline (optional authoritative overrides)

Result:
- identical state on every peer

---

## Branching

A branch is created by selecting a historical cut:

- node ID
- frontier snapshot
- or timestamp boundary

Then replaying forward into a new room.

---

## Fork Semantics

Forking produces:

- new room ID
- copied DAG prefix
- independent future mutations

---

## Why this matters

This enables:

- versioned collaboration
- sandbox environments
- audit-grade replay systems
